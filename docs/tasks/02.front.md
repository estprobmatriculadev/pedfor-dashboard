# Task 02 — Front-end do Dashboard

## Objetivo

Construir a interface do dashboard com foco em visualização clara, responsiva e orientada à tomada de decisão.

---

## Objetivos da interface

O dashboard deve permitir ao usuário:

- visualizar os principais indicadores;
- compreender rapidamente a situação atual;
- aplicar filtros;
- detalhar informações;
- identificar tendências;
- identificar problemas ou situações que necessitam de atenção.

---

## Estrutura visual

A interface deve possuir, quando aplicável:

### Cabeçalho

- título do dashboard;
- contexto/período;
- identificação do usuário;
- ações globais.

### Filtros

Os filtros devem ser apresentados de maneira clara.

Exemplos:

- período;
- unidade;
- categoria;
- status;
- responsável;
- modalidade.

Os filtros disponíveis devem ser definidos pela especificação dos dados.

### Indicadores

Utilizar cards para os principais KPIs.

Cada KPI deve possuir:

- nome;
- valor;
- unidade;
- período de referência;
- eventualmente comparação com período anterior.

### Visualizações

Utilizar:

- gráficos;
- tabelas;
- rankings;
- indicadores de tendência;

somente quando agregarem informação.

---

## Estados da interface

Todo componente que depende de dados deve possuir:

### Loading

Informar visualmente que os dados estão sendo carregados.

### Empty

Informar quando não existem dados para os filtros selecionados.

### Error

Apresentar mensagem compreensível ao usuário.

### Success

Apresentar os dados corretamente.

---

## Responsividade

Validar pelo menos:

- desktop;
- tablet;
- celular.

---

## Acessibilidade

Validar:

- navegação por teclado;
- contraste;
- labels;
- foco;
- leitura dos indicadores;
- uso de tabelas e gráficos.

---

## Critérios de aceite

- [ ] Dashboard possui layout definido.
- [ ] KPIs estão implementados.
- [ ] Filtros estão implementados.
- [ ] Gráficos estão conectados aos dados.
- [ ] Tabelas possuem estados de carregamento.
- [ ] Estados vazio e erro estão implementados.
- [ ] Interface é responsiva.
- [ ] Interface possui acessibilidade básica.
- [ ] Não existem regras de negócio críticas duplicadas no frontend.
